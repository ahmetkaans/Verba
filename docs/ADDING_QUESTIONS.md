The rules are the owner's (AGENTS.md rules 1, 3, 4, 9, 10): ask first, lorem ipsum for names the owner has not fixed, never decide open questions, and **draft → check → self-audit → review → owner's go-ahead → write**. ## Shapes (the correct answer is always FIRST; the game shuffles)
- `mc`: `{ "type": "mc", "prompt": "… ___ …", "options": [correct, w1, w2, w3], "explanation": "…" }` (Hard and Very Hard: if all 3 wrong options are from other themes, the audit names the closer option you considered and why you rejected it; a closer option that could be right is never used)
- `tf`: `{ "type": "tf", "prompt": "…", "answer": true, "target": "word", "explanation": "…" }` (4 true and 4 false in a quiz; false statements: absurd or opposite at Easy, one wrong detail at Hard and Very Hard but still clearly false; at most 1 true statement a bare definition)
- `fill`: `{ "type": "fill", "before": "…", "after": "…", "answer": "x", "bank": ["x", "w1", "w2"], "explanation": "…" }` (bank of 3 or 4, the answer first)
- `match`: `{ "type": "match", "prompt": "Match each word with its meaning.", "pairs": [ { "left": "…", "right": "…" } ×4 ], "explanation": "…" }`
- Optional: `target` (the dictionary form when the answer is inflected: "laughs" → "laugh"), `targetType` (the answer has several word types), fill `accept: [...]`. The full table is README "Question types".
- **Dialogue (two or more people talk in one question; owner, 2026-11-22):** put a **line break `\n` before each speaker after the first**, in the `prompt` (mc, tf) or in `before` / `after` (fill; the blank stays inside its speaker's line). At most 3 lines; the words do not change. Forms: `Anna: \"...\"`, `Ali says, \"...\"` (also *asks*, *answers*), or two quotes in a row. Good: `"prompt": "Anna: \"What's your ___, Tom?\"\nTom: \"It's 130 Green Street.\""`. Bad (check 35 gives an ERROR): the same text with a space instead of `\n`. A single speaker needs no `\n`. The game shows one speaker per line with the name in bold, so this works for every level and every future theme without a code change. README "Dialogues" has the rest.
- Key: `"A1|vocabulary|<N>|<mc|tf|fill|match>|<easy|medium|hard|veryhard>"`, with N as in the topics list (no leading zero: `|4|`, not `|04|`). A theme has 16 quizzes; mc, fill and tf quizzes have 8 questions; matching quizzes have a variable length (README "Matching quizzes have a variable length").
- Each question is **one line** (a matching question has its pairs on extra lines). The file part between `Object.assign(GAME_DATA.questions, ` and `);` must stay valid JSON.

## Steps
1. **Draft** in `.gitignore/drafts/themes/A1_vocabulary_<N>_<type>.json` (same shape as the bank: `{ "<key>": [ ...8 questions... ] }`); new glossary meanings in `A1_vocabulary_<N>_glossary.json` (`{ "A1": { "word": ... } }`). Nothing goes into `game/` yet.
2. **Check the draft:** `python -I .gitignore/tools/check_questions.py --draft <file> --draft-glossary <file>` (since 2026-11-24 the checks run in Python; the old `check_questions.ps1 -Draft ...` is frozen as the oracle and gives the same report). Fix every error, read every warning. **Run it after EVERY draft file (not only at the end), and make a check the last step of every working turn, never an edit** (a glossary draft that was edited after the last check turned out to be invalid JSON, 2026-11-21). Change files with small Edit calls only: never a text replace in PowerShell, never a whole-file rewrite for a few words. Do not print the whole report in the chat: run `powershell -ExecutionPolicy Bypass -File .gitignore/tools/questions/check_brief.ps1 <the same arguments>` instead. It keeps the full report in `%TEMP%\check_brief_full.txt` and prints the summary, every error, the warnings counted per check (two examples each) and what is new since the last run.
2b. **Check repetition (owner, 2026-11-22: "too many repetitive sentences in structure"):** when the four type files are drafted, run `python -I .gitignore/tools/questions/repetition_report.py --draft <N>` (about 1 second; `--theme <N>` for a written theme; `--files a.json b.json` for other draft files; no option = one line per written theme). It counts, inside the theme: a wrong option or bank word used more than 4 times, an explanation opening (first 3 words) used more than 6 times, "A/An/To X is ..." explanations above 45 %, a name used in more than 6 questions, a 5-word phrase in more than 3 questions. It must say `RESULT: 0 repeated pattern(s)`; fix by changing the question files, never by loosening the limits. A "-ed / -ing" pair question (answer *boring*, wrong option *bored*) is not counted: the pair is its point. **To fix a WRITTEN theme:** run `python -I .gitignore/tools/questions/repetition_propose.py --theme <N> --limit 6` (changes nothing; it chooses new wrong options with running counts and writes a sheet `.gitignore/drafts/proposals/propose_theme_NN.md` with each sentence filled in with the new word, plus a swaps file); READ every line (clearly wrong? could it also be right? reads well?), delete the lines you do not accept, apply with `repetition_fix.ps1 -Theme <N> -Swaps <file>`, then run the repetition report, the check script, `set_versions.ps1` and the browser load test. "POOL TIGHT" and "NO CANDIDATE" lines are the owner's decision (a small word pool), never decided silently. **Closeness of wrong options (owner, 2026-11-22):** add the theme's words to `.gitignore/plans/questions/word_groups.txt` (group, family, `must:` sets; read its header) and run `python -I .gitignore/tools/questions/option_check.py --theme <N> --detail`; it must have no VETO and no UNKNOWN; every TOO EASY / TOO CLOSE line is judged by a reader (README "Wrong options: closeness check"). A level without rows in `option_settings.txt` stops the tool: ask the owner for its numbers. While drafting, mix the shapes of explanations (scene first, "When you ...", "X means ...", a contrast) and give every word a different scene in each question type (the same scene twice, for example the same sentence in Multiple Choice and in Fill, is a repeat the script cannot see: look for it in the by-word table of the readable file). The written themes 0 to 13 were measured the same day and several limits are broken there (see README, "Question repetition").
3. **Self-audit twice** (the eight points in the Workflow section), write `<Prefix>_audit.md`, make the readable file with `.gitignore/tools/questions/make_readable.py --prefix A1_vocabulary_<N>` (it also writes the joined `<Prefix>_ALL.json`), run the **helper review (3b)** once all four question types of the theme are drafted, fix what is real and run `make_readable.py` again, then show the readable file and the helper table to the owner and remind them to ask for the review. Do not reread the readable file to check your work (it only repeats the JSON and costs tokens); when something must change, fix the `.json` files and run `make_readable.py` again.
3b. **Helper review** (owner approved 2026-11-19; **once per theme**, after all four types are drafted and `make_readable.py` has made `<Prefix>_ALL.json`; it replaces the old blind-solve step, see "Helper review" below): `python -I .gitignore/tools/questions/review_sheet.py --draft .gitignore/drafts/themes/<Prefix>_ALL.json --draft-glossary .gitignore/drafts/themes/<Prefix>_glossary.json --out-dir <scratchpad folder>`, start ONE helper agent with the text of `<folder>\prompt.txt` as its prompt (model Sonnet), save its reply, then `... review_sheet.py --score --out-dir <folder> --findings <reply file>`.
4. **Review** only when the owner asks: `python -I .gitignore/tools/check_questions.py --worksheet --draft <file>` and the Review checklist, with a quote as evidence for every hard item. A "cold review" means the owner opens a new chat and pastes the readable file there; never start a helper agent yourself (the one exception is the helper review, step 3b).
5. **Write** only after the owner's go-ahead. First save the whole-bank `bank_index.py` output (no options) in the scratchpad, for the comparison in step 6. Then small, exact Edit calls (one question per line, inside the array of its key; glossary meanings next to their alphabetical neighbour in `a1.js`). Use the Edit tool, never PowerShell strings.
6. **Verify the theme:** `python -I .gitignore/tools/check_questions.py --only 'A1|vocabulary|<N>|'; $LASTEXITCODE` (the number must be 0; end the theme number with `|`). Then the whole bank once, with no options (about 1 second). Compare `bank_index.py` before and after: only the intended counts change.
7. `powershell -ExecutionPolicy Bypass -File .gitignore/tools/set_versions.ps1`, then the same with `-Check` (must say OK). For a question-only change (AGENTS.md rule 6): the console shows no errors, the new quizzes play in a normal browser, and `set_versions.ps1 -Check` says OK. Skip the theme, motion and phone tests unless code changed.
8. **A new theme data file only** also needs: the script tag in `game/index.html`, the README Data file table, the plan, the DESIGN names list (README map, row "A vocabulary theme"), and "Written so far" under README "Content (questions)". The theme's name is already in `TOPICS_BY_SECTION` (`js/topics.js`, all 15 A1 vocabulary names exist): look, and add one only for a brand-new topic. Then `powershell -ExecutionPolicy Bypass -File .gitignore/tools/check_filemap.ps1` (must say OK).
9. **Commit** only when asked, with a `CHANGELOG.md` entry (AGENTS.md rule 7).

## Helper review (drafts of a new theme, and written themes; owner approved 2026-11-19)
One helper agent reads one sheet file and returns only findings. It is the one allowed use of a helper agent (owner's exception); it replaced the blind-solve step. Never read the questions in this chat. `review_sheet.py` (header = full usage) does the rest:
1. **Make the sheet:** `-Draft <Prefix>_ALL.json [-DraftGlossary <Prefix>_glossary.json] -OutDir <scratchpad folder>` for a new theme, or `-Theme <N>` for a written one. It writes `sheet.md` (one line per question, answers shown, two-pass rubric, 3 planted bad "canary" questions, one in each third of the sheet, the new pop-up meanings), `prompt.txt` (the exact helper prompt) and `map.json` (writer only).
2. **Run the helper:** ONE helper, model Sonnet, prompt = the text of `prompt.txt` unchanged. It reads only `sheet.md`; never give it `map.json`, the draft files or the key. Save its reply to a text file.
3. **Score:** `... review_sheet.py --score --out-dir <folder> --findings <reply file>`. **NOT TRUSTED** (exit 1) only when a planted question was missed: run the sheet again with the same prompt. The canaries are the evidence: one is always a second-answer canary placed in the LAST third of the sheet, so catching it shows the reader got to the end. The `READ:` line is only the reader's claim: a missing or incomplete line is a note, not a reason for a follow-up message (changed 2026-11-19: it caused extra round trips). Record so far: with the plain prompt the second-answer canary was missed 2 times in 15 reads (the other 13 caught it); with the two-pass prompt now in `prompt.txt` it was caught 3 of 3.
4. **Verify every finding** against the sheet line the scorer prints. Findings are claims: on themes the owner had already reviewed about 90% were false alarms (the reader does not know every owner decision, cannot see the word lists, and over-reads), so never forward the raw list. Fix the real ones (draft files for a new theme, Edit calls for a written one: draft, check, review, go-ahead as always), run the check script, and for a new theme run `make_readable.py` again.
5. **Tell the owner** in a short table: finding, kept or rejected, why. The owner's review stays the last word (the helper is the same kind of model as the writer).
6. **Cost, measured 2026-11-19:** about 75k tokens and 30 to 80 seconds inside the helper per theme of about 110 questions; the reply in this chat is about 1k tokens when it follows the limits. The rubric in the script is a short copy of the Review checklist: change it with the checklist (AGENTS.md rule 11). `blind_sheet.ps1` (answers hidden, the reader picks) is kept as an optional extra for Matching quizzes; on theme 9 it matched 112 of 112 and found nothing (68k tokens).
7. Measured on theme 6 (110 questions, 2026-11-19): Sonnet with the first prompt about 72k tokens and 34 s (53 flagged ids, about half noise, reply about 3.5k tokens in this chat); Haiku with the tuned prompt about 85k tokens and 68 s (4 findings on real questions). Both caught both canaries and reported every id read, so the cheaper model was **not** cheaper in tokens or time (the price per token was not measured). Neither reader flagged the three passive sentences that check 29 finds for free in that theme: **run the script checks first; the readers are for what scripts cannot see** (second answers, natural English, narrow meanings). The prompt change and the model change happened together, so their effects are not separated.

## Why this file and its "do not read" list exist (2026-11-19)
- A question task used to read about 75k tokens before writing (the File map 10k, the whole "Content" and "Question content method" parts 22k, whole plan and word files, a whole theme file 8k, the glossary 13k). This recipe needs about 25k. The owner's quality rules (Review checklist, self-audit) are **kept in full**; only the reading around them was cut.
- **Do not split `glossary/a1.js` into several files.** The data files are joined with `Object.assign`, which is shallow: a second file with the key `"A1"` would replace the first. Use `bank_index.py --word` and read only the line range.
- **Do not trust a plain `^## ` search of the README.** `## Food and Drink` is an example inside a code fence (in "Target-word plans"), not a section; `show_section.ps1` skips code fences.
- `.claude/settings.json` (JSON has no comments, so the reason is here) denies Read for `.gitignore/archive/**`, `.gitignore/drafts/**/*_ALL.json`, `.gitignore/tools/playthrough.js`, `.gitignore/audio/**/*.mp3`, `.gitignore/audio/**/*.wav`, `.gitignore/audio/third_party/piper_old/**`, `.gitignore/audio/voices/**` and `.gitignore/audio/piper15/venv/**`: they are 40k to 140k tokens each (the audio, voice and Piper files are binary and useless to read) and nothing in a question task needs them. The Edit tool cannot change a file it may not read; lift the line for a moment if `playthrough.js` must change, then put it back.
- **Why the kit, the table and "check after every file" exist (2026-11-21):** the first drafts of themes 11 to 13 cost far more than planned: many natural words were not A1 words (*sky, pet, hole, ground, side, top, direction*), files were rewritten in full, one PowerShell text replace corrupted two files, whole reports were printed in the chat, and three themes in one chat made every step more expensive. The fix is one theme per fresh chat (the owner opens it), the drafting kit read once, the check after every file and the multi-meaning table at plan time. The saving is expected, not measured. Reasons and the owner's decisions: README "Confirmed decisions".
- Full reasons and measurements: README Roadmap item 14, d.

## Risks the checks do not catch
A second possible right answer, an unnatural sentence, a sentence that can be read rudely, a word above the level. Only reading catches them (Review checklist).
