# Question method for every level (A1 to C1)

Written 2026-11-23 with the owner; linked from AGENTS.md, RULES_FULL.md (rule 9), ADDING_QUESTIONS.md (step 7) and the README map. The tools are listed in "The tools" below. A2 rows of `option_settings.txt` exist since 2026-11-23, and `plans/questions/level_share_exceptions.txt` holds the owner's exceptions to the level rule (an answer whose word type has too few words in the theme, for example *fresh*: up to 2 lower-level wrong options).

This is the method for **new** question work at any level: A2 vocabulary first (pilot: Food and Cooking), later B1 to C1, and new A1 work such as the A1 grammar topics. A1 vocabulary is finished and keeps its recipe in `docs/ADDING_QUESTIONS.md`. The rules of AGENTS.md (ask first, draft, check, review, go-ahead, then write) and the README sections "Never ambiguous", "Target words and difficulty", "How similar the wrong options are", "Writing the questions", "Review checklist" and "Question repetition" all stay true; this file does not copy them, it only says the order and what changes. Where this file and the README disagree, stop and ask (rule 10).

## The level rule (owner, 2026-11-23)
1. **Target words first.** Every new word of the level, in the theme's list, is tested, as at A1.
2. **Lower-level words are allowed around them** (sentences, explanations, wrong options, bank words), never forced, and **never the tested word** (an A1 word already had its quizzes at A1). For B1 the lower levels are A1 and A2, for B2 A1 to B1, for C1 A1 to B2. A1 has no lower level.
3. **Wrong options: the current level is the majority** (vocabulary themes only; for grammar topics see "Grammar topics" below). At least 2 of the 3 wrong options of a question are words of the current level (the bank words of a Fill question: the same share). At A1 this rule does not apply.
4. Every wrong option still passes the second-answer check, whatever its level.
5. **One word type per level (owner, 2026-11-24).** When a word is listed in `ORG_<LEVEL>_WORDS.md` ("word types (full list)") with a word type that is new at this level, only the type(s) listed THERE may be tested, never a type already taught at a lower level. This holds for the whole tested part: the answer, the wrong options, the Fill bank words and the Matching words. Example: *free* is an A1 adjective and an A2 adverb, so at A2 it is tested, and offered as an option, only as the adverb (*Children enter free*). When the level lists several types for one word (*taste*: noun, verb), every question names one of them (the plan line "Tested types"). The rest of a sentence, the explanations and the pop-up meanings keep Rule 2 below (any type of an A1 or A2 word).

## The two word rules (owner, 2026-11-23)
**Rule 1, the tested part.** The tested part (the correct answer, the wrong options, the Fill bank words, the Matching words) of a vocabulary-theme question comes from the theme's own words of the level plus its "Goes well with" words. Lower-level words may be added when the theme has too few close words; most wrong options (at least 2 of 3) still come from the theme. Words of other themes are not used: when a theme runs short, the writer tells the owner and asks. (A grammar topic follows the section "Grammar topics" below.)
**Rule 2, everything else.** The rest of a sentence, the explanations and the pop-up meanings may use words of this level and of the lower levels, never a higher level.
The same text is in `ORG_A2_WORDS.md`, "Rules for A2 questions". Check 38 of `check_questions.py` and check B10 of `blueprint_check.py` (the blueprint file starts with a line `theme: <theme name>`) report a wrong option from another theme as a warning; the writer then changes the option or asks the owner when the theme runs short.

## Grammar topics (owner, 2026-11-24; A2 and higher)
A grammar question often tests a form of a lower-level word (*go / went / gone*, *wash / washes*), so the vocabulary rules above are changed for grammar topics. Checks 36 and 37 are for vocabulary quizzes only.
1. **The tested grammar is the level's own grammar.** A2 grammar is tested in A2, B1 grammar in B1, and so on; the topic list in `ORG_<LEVEL>_WORDS.md` and the plan decide what belongs to the level.
2. **The tested part (answer, wrong options, bank words) may use words of this level and of every lower level, never a higher level.** The majority rule (rule 3) and "never the tested word" (rule 2) do not apply, because the point of the question is the grammar, not a hard word. Every wrong option still passes the second-answer check, the word-type check and the same-form rule (*went / came / ate*, not *went / come / eating*).
3. **The sentence carries the level's vocabulary.** The sentence (not the options) should have at least one word of the current level. Check 40, a warning, not an error; the number is `GRAMMAR_MIN_LEVEL_WORDS`.
4. **Repetition.** A form may come back in a new sentence with a different subject and setting (a "recast": good). The same sentence frame with one word swapped is not allowed. Use checks 18, 20, 22 and 26 and `repetition_report.py`; add a sentence-skeleton or per-word limit only when a real topic shows the problem (owner, 2026-11-24).
5. **A1 Grammar** has no level rule, so none of this applies there.
Not decided yet: the Check 29 lists (grammar above the level) for B1 to C1, and new irregular forms for the `IRREGULAR` table; add them when those levels start.

### Steps for a grammar topic (owner, 2026-11-24)
The numbered steps below are written for vocabulary themes. For a grammar topic change them like this; everything else (draft, check, self-audit, review, go-ahead, write) stays.
- **Step 2, plan: add a variety plan.** Besides the topic's forms and words (the Words line, "Goes well with" and Exceptions of `ORG_<LEVEL>_WORDS.md`), the plan lists the sentence types the topic must cover (positive, negative, question, short answer, time words in different places), the subjects (*I, she, the children, my teacher*) and the settings (home, school, travel, shopping). Every planned question gets one type, one subject and one setting **before** any sentence is written. This is how repeated sentence skeletons are prevented; a script only sees them afterwards.
- **Step 3, blueprint: a table, not the theme tools.** `blueprint_solve.py` and `blueprint_check.py` read a vocabulary theme's words and its level share, so they are not used for grammar. Make the table by hand: the form tested, three wrong options that are mistakes real learners make (*has went, has go*; same word type, same form rule), the sentence type, subject and setting. The quick semantic scan still applies.
- **Step 4, sentences:** a form may come back in a new sentence with a different subject and setting (a recast); never the same frame with one word swapped. Run the check after every file and read checks 40, 18, 20, 22, 26 and 29.
- **Step 6, repetition:** `repetition_report.py --files <draft files>`; look at the sentence openings and frames by hand too, because the script does not yet see a repeated skeleton.
- **Who does what:** scripts count, compare and remember every question of the topic at once; the writer judges meaning, natural English, good wrong options and whether a flagged repeat is a useful recast or a lazy copy. A mistake that keeps coming back becomes a new script check, not a note to be more careful.

## Level settings
| Setting | A1 | A2 | B1 to C1 |
|---|---|---|---|
| Sentence length | about 12 words | about 15 words | owner decides when the level starts |
| Weak wrong options at Hard and Very Hard | allowed when a closer word could also be right | not allowed | not allowed |
| Grammar words in explanations | none | rare: *noun, verb, adjective*, only when needed | owner decides |
| Grammar in sentences | A1 limits (Review checklist, section 2) | see below | owner decides |
| Option closeness numbers (min family / max group / min group) | A1: Easy 0/1/0, Medium 0/2/0, Hard 2/3/0, Very Hard 3/3/1 | A2 (owner, 2026-11-23): Easy 1/1/0, Medium 2/2/0, Hard 3/3/1, Very Hard 3/3/2 | owner decides when the level starts |

**A2 grammar in sentences.** The 24 topics of `ORG_A2_WORDS.md` (section 2) may be used. *Normal use:* simple tenses, *can / could*, *going to*, *will*, *have to*, *should*, comparatives and superlatives, countable and uncountable nouns, *like + -ing*, *want to*. *Light use* (a few questions per quiz, never in the tested part of a vocabulary question): past continuous, simple present perfect (*have / has + past participle*), first conditional, common phrasal verbs. *Not at A2:* passive, second and third conditionals, past perfect, reported speech, *so ... that*.

## Steps (one theme per fresh window; the owner opens it)
1. **Read once.** The level's kit `draft_kit_<LEVEL>.md`, the plan of the theme, the README sections above (`show_section.py`).
2. **Plan** (owner approves): the theme's words split into four difficulties (at least 8 each), the multi-meaning report, Matching sizes, the closeness numbers for the level if the owner has not set them.
3. **Blueprint** (new). Before any sentence, one table per difficulty: answer word, three wrong options, question type, the word's meaning. Wrong options come from a close group in the same theme and word type (`word_groups.txt`). Make the first table with `python .gitignore/tools/questions/blueprint_solve.py --level A2 --theme "<theme name>"` (private; added 2026-11-23): it proposes the wrong options of every Multiple Choice and Fill row from the approved plan under the same rules as the checker, and marks a row `POOL TIGHT` or `NO CANDIDATE` when the theme runs short (then stop and ask the owner; the theme's words must be in `word_groups.txt` first). Run `blueprint_check.py` on the result (closeness, level share, repeated wrong options; command in "The tools"). The script stops after 15 seconds at the most; a row marked `## FILLER` has an unrelated option (allowed at Easy and Medium) and needs your eye first; rows you fixed by hand can be kept with `--pin <file>` while the rest is solved again. **Quick semantic scan (about 1 minute):** the script does not judge meaning, so read every row and ask whether a natural clue can rule out each close option; swap a doubtful option now, while it is only a table row (free-slot options at Easy and Medium are often unrelated lower-level words, and words with a second meaning, like *present* or *light*, need a look). Fix the table, not the sentences.
4. **Sentences**, one question type at a time, with a new scene for each word in each type. **Distinct contexts across modes (owner, 2026-11-24):** when the same target word is tested in both Multiple Choice and Fill in the Blanks, the two items use different settings, actors and sentence frames: never the same opening clause or the same scenario for one word in two modes (for example "The shop has a large ___ of ..." in both). Before the self-audit, list every word with its items of all types side by side and compare their openings. Run the check script after every file (`check_brief.py`), small Edit calls only.
5. **Self-audit**, one full pass: for every wrong option the best argument that it could also be right (a quoted option, not "looks fine"); every sentence read twice, once for a bad reading. Then a second pass **only** over the questions that changed or that a script flagged. The audit is a table the owner can read.
6. **Repetition and closeness checks** on the finished files (`repetition_report.py`, `option_check.py`; commands in "The tools"), then `make_readable.py`.
7. **Helper review**, once per theme (docs/ADDING_QUESTIONS.md, "Helper review"); verify every finding; report kept and rejected.
8. **Owner's review.** Write into `game/` only after the owner's go-ahead; then the whole-bank check, `set_versions.py --check`, the browser load.

## Lessons from the first A2 themes (owner and writer, 2026-11-24)
Written after A2 themes 0 and 1. Each lesson names the mistake it prevents.
1. **Do the pool math BEFORE the plan is approved.** Count, for every difficulty, how many words of each word type the theme has (adjectives, nouns, verbs) and how many wrong options each type needs: about 3 per Multiple Choice question and 2 to 3 per Fill question, each option used at most 4 times in the theme (repetition limit), at least 2 of 3 from the level. A theme whose adjective or verb pool is too small (Daily Life and Habits: 11 adjectives, 7 of them near synonyms) must be solved at plan time (exceptions, other test counts), not after the sentences are written. `blueprint_solve.py` shows POOL TIGHT / NO CANDIDATE: stop and tell the owner at the first sign.
2. **Slot arithmetic.** A quiz needs 8 DIFFERENT answers per type (blueprint check B2). Skipping a word in one type only works if the difficulty has spare words; a plan like "test the seven near synonyms in only three types" cannot be built when each difficulty has exactly 8 words.
3. **Collocation first for synonym clusters.** Near synonyms (*daily, everyday, regular, usual, typical, ordinary, normal*) are never made safe by hiding them: only the true pairs are vetoed (*daily / everyday*, *ordinary / normal*), and every sentence uses a collocation that only the answer fits (*daily newspaper*, *regular customer*, *as usual*, *ordinary guy*, *everyday clothes* with options that are not synonyms). Where no such sentence exists, the options are non-synonyms and the closeness warning is accepted and written in the audit.
4. **Second answer beats closeness.** When the closeness check and the second-answer check disagree, the second-answer check wins (a TOO EASY warning is accepted and recorded in the audit; a second right answer never is).
5. **A new word type needs a new scene.** At A2 a known A1 word (*first, start, wait, sleep, wash, later, last*) is tested only in its new type (noun, adjective, "taking time"): write the noun use (*a long wait*, *a quick wash*), never the old one.
6. **Check the options' word types and the lists before sentences.** Options must be the same word type as the answer, A1 or A2 words only (*vet, tidy, monster, knife-type violence* are not), no British spellings (*movie*, *apartment*), and no sentence that needs "so ... that" or the passive.
7. **A generator script keeps files valid.** Write the draft as a small Python data script (`.gitignore/drafts/gen/`) that dumps the JSON files, so one fix is one line and every file is always valid JSON.
8. **Status line after each stage** (owner, 2026-11-24): after the plan, the groups, the blueprint, the files and the checks, say in one line what is done.
13. **When a theme cannot meet all rules together, decide it at plan time.** A2 theme 1 (11 adjectives, 7 near synonyms, 6 verbs) could not keep the repetition cap of 4, the level share of 2 of 3 and no second answer at once; swapping options failed. What worked: `pool_check.py` before the plan, level-share exceptions (up to 2 A1 fillers) for the Easy and Medium adjective and verb answers (owner, 2026-11-25), a depth-first repair search that keeps every other row, a reader's check of every changed sentence, and the helper review. A word in the reader's FORBID list (a near synonym that fits the sentence) is never offered again.
9. **A check that read nothing must not pass (2026-11-24).** `repetition_report` reads ONE question per line. The joined `<Prefix>_ALL.json` is pretty-printed, so the report read zero questions and printed `0 repeated pattern(s)`; `draft_check` and I repeated that PASS for A2 themes 0 and 1, and theme 1 really had 16 wrong options over the limit (*brush* 9 times, *later* 8). Rules: give the repetition report the four TYPE files (`_mc`, `_fill`, `_tf`, `_match`); the report now stops with a message when a file keeps a question on several lines; and every future check must refuse an input it cannot read instead of passing on empty data. A PASS that comes from a check that saw nothing is the worst kind.
10. **Tool output that depends on a hash table has no fixed order.** The PowerShell originals printed word types, tied counts and theme lists in hash-table order; the Python tools print them sorted or in list order. `golden.py` compares them after one shared normalisation (`canon`), so a harmless order difference is never a failure and a real difference always is.
11. **Compare names the way the game does.** The recording of *ice cream* is `ice-cream.mp3` and of *o'clock* `oclock.mp3` (`wordAudioFile` in `js/word-audio.js`); an audit that compares raw words reports false "missing" files. `sync_check.py` uses the game's rule and checks that the game and `publish_audio.ps1` give the same name for every word.
12. **Pool tightness shows in the counts, not only in the solver.** When a theme has few words of a type (Daily Life and Habits: 11 adjectives, 19 nouns), a clean blueprint becomes repeated wrong options once the sentences are written and risky options are replaced. Run `pool_check.py` before the plan, keep the blueprint's option counts in view while writing, and run `draft_check.py` (repetition on the type files) after EVERY file, not only at the end.

14. **Check each type file the moment it is written (owner, 2026-11-25).** Redoing A2 themes 3 and 4 and writing theme 2 needed 3 to 4 fix rounds each for off-list words, long sentences, passives and a / an giveaways, because four type files were generated in one run and checked together. When a generator writes all types at once, it runs `check_brief.py` on each type file right after writing it (a `lint(path)` call at the end of each dump step, in `.gitignore/drafts/gen/a2_2_*.py`, `a2_3.py`, `a2_4.py`) and the writer fixes the errors before the next type. A separate shared helper or a new pre-check tool is NOT built: add one only if the next themes still show the same fix rounds. Also run `pool_check.py` and the solver before the plan is approved, and put any needed level-share exception in the approval question (lesson 1).

## Dual working principle (owner, 2026-11-24; AGENTS.md rules 15 and 16)
Every change to Verba is made by two people at once. **As a software engineer:** scripts, game code, data structures and the file layout are modular, fast, deterministic and regression-free. **As an experienced EFL teacher:** every word split, wrong option, collocation, hint and game mechanic is pedagogical, fair and clear for a learner at that CEFR level. Teaching quality is never sacrificed for a quick code hack, and fragile or bloated code is never written for a narrow teaching edge case; when the two pull apart, the writer says so and the owner decides.

## What each step prevents (A1 mistakes)
| Mistake | Step |
|---|---|
| Second possible answer, "0 warnings" | 3 (closeness), 5 (argument per wrong option) |
| Repeated wrong options, names, scenes | 3, 4 (new scene), 6 |
| Weak unrelated wrong options at A2+ | 3, level settings |
| Words above the level, wrong word type | 1 (kit), check script |
| Bad second reading | 5 |
| Many-meaning words (chicken, light) | 2 (multi-meaning report) |
| Token cost: whole reports, whole rewrites, three themes in one chat | one theme per window, `check_brief`, Edit calls, step 5 second pass only on changes |

Rule 16 adds four habits to the two hats: keep every folder tidy and modular, write each lesson into the right permanent file, keep data and asset wiring synchronized by an automated check, and optimize only with small backward-compatible changes plus the whole regression suite (the list is in `docs/RULES_FULL.md` rule 16).
